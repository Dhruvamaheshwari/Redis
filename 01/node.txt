REDIS LEARNING PROJECT - FOLDER NOTES
======================================

Purpose
-------
This folder contains a small Node.js service for learning how Redis and MongoDB can be used from an Express application.

Project files
-------------
- package.json: Project metadata, scripts, and npm dependencies.
- package-lock.json: Locked dependency versions generated by npm.
- src/index.js: Express server, Redis client, MongoDB connection, and API routes.
- docker-compose.yml: Local Redis and MongoDB development services.
- node_modules/: Installed npm packages. This is generated and should normally not be committed.

Technologies
------------
- Node.js
- Express 5
- ioredis 6
- Mongoose 9
- Redis 7 Alpine
- MongoDB 7
- Docker Compose

How the application works
-------------------------
1. The Node.js process starts an Express server on port 4000.
2. ioredis creates a Redis client using REDIS_URL, or redis://localhost:6379 by default.
3. GET /redis sends PING to Redis and returns the Redis response.
4. GET /mongo connects to MongoDB only when the first MongoDB request arrives, then returns the connected database name.
5. Redis uses append-only persistence and stores data in the redis-data Docker volume.
6. MongoDB stores data in the mongo-data Docker volume.

API endpoints
-------------
GET http://localhost:4000/redis
Expected response:
{"redis":"PONG"}

GET http://localhost:4000/mongo
Expected response:
{"mongo":"connected","database":"chai_aur_redis"}

Prerequisites
-------------
- Node.js and npm
- Docker Desktop with Docker Compose support

Install dependencies
--------------------
From this folder, run:

npm install

Start the databases
-------------------
From this folder, run:

docker compose up -d

Check running containers:

docker compose ps

Start the Node.js server
------------------------
Development command:

npm run dev

The server should listen on:

http://localhost:4000

Stop the databases
------------------

docker compose down

The named volumes remain available. To remove the containers and stored database data:

docker compose down -v

Environment variables
---------------------
REDIS_URL
- Optional.
- Default: redis://localhost:6379
- Example: redis://localhost:6379

mongo_url
- Optional in the current source code.
- Default: mongodb://localhost:27017/chai_aur_redis
- Note: The source currently reads the lowercase name mongo_url. Keep that spelling when testing without changing the source.

Docker services
---------------
Redis:
- Image: redis:7-alpine
- Host port: 6379
- Container name: chai-aur-redis
- Persistence: redis-data volume
- AOF persistence is enabled with appendonly yes.

MongoDB:
- Image: mongo:7
- Host port: 27017
- Container name: chai-aur-mongo
- Default database configured by Compose: chai_aur_redis
- Persistence: mongo-data volume

Useful checks
-------------
Test Redis from the command line if redis-cli is installed:

redis-cli -h localhost -p 6379 ping

Expected result:

PONG

Test the API from PowerShell:

Invoke-RestMethod http://localhost:4000/redis
Invoke-RestMethod http://localhost:4000/mongo

Common problems
---------------
- Connection refused on /redis: start Redis with docker compose up -d and verify port 6379 is free.
- Connection refused on /mongo: start MongoDB and verify port 27017 is free.
- Port already in use: stop the process using the port or change the port mapping in docker-compose.yml and the connection URL.
- npm command not found: install Node.js and restart the terminal.
- Docker command not found: install Docker Desktop and make sure it is running.
- MongoDB data is not reset by docker compose down. Use docker compose down -v only when deleting learning data is acceptable.

Learning ideas
--------------
- Add Redis SET and GET routes.
- Add a short-lived Redis cache around a MongoDB query.
- Add JSON request parsing with express.json().
- Create a Mongoose model and persist a document.
- Add graceful shutdown for the Express server, Redis client, and MongoDB connection.
- Add error handling for unavailable databases.
- Move connection URLs into a .env file with a dotenv package.
- Add tests for /redis and /mongo.

Important reminder
------------------
This is a learning project. Do not expose the Redis or MongoDB ports publicly without authentication, network restrictions, and proper production configuration.
